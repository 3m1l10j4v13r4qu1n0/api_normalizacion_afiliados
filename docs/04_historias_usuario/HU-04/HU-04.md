Historia de Usuario N°4
**Como** Usuario Administrativo,
**quiero** modificar los datos de un afiliado existente,
**para** mantener su información actualizada.

Tarjeta
Los datos de los afiliados pueden cambiar con el tiempo. El sistema debe permitir actualizar solo los campos enviados y rechazar cambios que generen inconsistencias (afiliado inexistente o duplicados).

Criterios de Aceptación
- Dado un afiliado existente, cuando se envían datos de actualización válidos, entonces el sistema actualiza los campos enviados y confirma la operación.
- Dado que se envía un nombre o apellido vacío, cuando se intenta actualizar, entonces el sistema valida que no estén vacíos.
- Dado que el email enviado ya está en uso por otro afiliado, cuando se intenta actualizar, entonces el sistema rechaza el cambio como duplicado.
- Dado un ID de afiliado inexistente, cuando se intenta actualizar, entonces el sistema informa un error 404.

Specification by Example
- Actualización con datos válidos = afiliado actualizado
- Email en uso por otro afiliado = cambio rechazado
- ID inexistente = error 404

Acceptance TDD
- Probar actualización de afiliado válido
- Verificar rechazo de email duplicado
- Verificar error 404 para ID inexistente
