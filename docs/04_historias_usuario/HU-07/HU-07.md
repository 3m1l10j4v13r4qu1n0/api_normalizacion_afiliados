Historia de Usuario N°7
**Como** Usuario Administrativo,
**quiero** dar de baja un afiliado,
**para** marcarlo como inactivo sin eliminarlo físicamente.

Tarjeta
La eliminación de un afiliado debe ser una baja lógica: se marca como inactivo pero el registro permanece en la base de datos para preservar el historial.

Criterios de Aceptación
- Dado un afiliado existente, cuando se da de baja, entonces el sistema lo marca como inactivo (baja lógica) y confirma la operación.
- Dado un afiliado dado de baja, cuando se consulta, entonces no aparece en los listados de afiliados activos.
- Dado un ID inexistente, cuando se intenta dar de baja, entonces el sistema informa un error 404.
- Dado la operación de baja, cuando finaliza, entonces el registro permanece en la base de datos.

Specification by Example
- ID existente = baja lógica confirmada
- ID inexistente = error 404
- Afiliado inactivo = no aparece en listados activos

Acceptance TDD
- Probar baja lógica de afiliado existente
- Verificar error 404 para ID inexistente
- Verificar que el registro permanece en la base
