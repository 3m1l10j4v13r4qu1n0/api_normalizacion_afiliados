Historia de Usuario N°1
**Como** Sistema Cliente,
**quiero** enviar una lista de afiliados para importar,
**para** validarlos, normalizarlos y almacenarlos en el sistema.

Tarjeta
Los datos de afiliados llegan en lotes desde distintas fuentes. El sistema debe controlar cada registro antes de almacenarlo, guardando solo los válidos y registrando los errores de los inválidos sin interrumpir el proceso.

Criterios de Aceptación
- Dado que se envía una lista de afiliados, cuando se procesa el lote, entonces los registros válidos se almacenan y los inválidos se registran como errores sin interrumpir la importación.
- Dado que un afiliado tiene un DNI ya existente, cuando se procesa el registro, entonces el sistema lo rechaza como duplicado y registra el error.
- Dado que un afiliado tiene un nombre, cuando se normaliza, entonces se almacena en mayúsculas y sin espacios al inicio ni al final.
- Dado que un registro tiene campos obligatorios vacíos, cuando se valida, entonces el sistema lo descarta y registra los errores de los campos faltantes.
- Dado que finaliza la importación, cuando se completa el proceso, entonces el sistema devuelve las métricas de procesados, válidos y errores.

Specification by Example
- Lote con 3 válidos y 1 con DNI duplicado = se almacenan 3, se registra 1 error, procesados 4
- Afiliado sin nombre = rechazado con error de campo obligatorio
- Registro con DNI "12.345.678" = se normaliza y almacena como "12345678"

Acceptance TDD
- Probar importación de lote con registros válidos e inválidos
- Verificar rechazo de DNI duplicado
- Verificar normalización de nombres y DNI
- Verificar renglones de métricas devueltas
