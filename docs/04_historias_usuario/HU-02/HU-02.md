Historia de Usuario N°2
**Como** Usuario Administrativo,
**quiero** registrar un afiliado individualmente,
**para** cargarlo validado y normalizado al sistema.

Tarjeta
A veces los afiliados se cargan de forma manual e individual. El sistema debe validar los datos ingresados antes de almacenarlos e informar los errores al usuario para corregirlos.

Criterios de Aceptación
- Dado que se ingresa un afiliado con los datos obligatorios completos, cuando se envía, entonces el sistema valida, normaliza y lo almacena.
- Dado que un campo obligatorio está vacío, cuando se envía, entonces el sistema informa el error y no persiste el registro.
- Dado que el DNI del afiliado ya existe, cuando se envía, entonces el sistema rechaza el registro como duplicado.
- Dado que se completa el ingreso, cuando el registro es válido, entonces el sistema confirma el alta del afiliado.

Specification by Example
- Afiliado con nombre, apellido y DNI válidos = almacenado
- Afiliado sin nombre = rechazado con error
- Afiliado con DNI duplicado = rechazado

Acceptance TDD
- Probar alta de afiliado válido
- Verificar error en campos obligatorios
- Verificar rechazo de DNI duplicado
